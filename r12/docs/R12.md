# R12 팔 실습

제공한 `R12_NO_USB_URDF_USD.zip`의 URDF, 내장 형상 USD 및 메시를 사용합니다. 원본 61개 파일의 SHA256을 확인했으며 원본 파일은 수정하지 않습니다.

## 구성

- 원본: `assets/vendor/R12_NO_USB_URDF_USD/` (대용량이므로 Git 제외).
- 파생 USD: `models/r12/r12_arm.usda`. 원본 USDC를 상대 참조합니다. 베이스를 world에 고정하고 바퀴·조향 8축을 고정 관절로 덮어씁니다.
- 파생 URDF: `models/r12/r12_arm.urdf`. 같은 8축을 고정하고 메시 상대 경로를 보정합니다.
- 행동: `arm_joint1`부터 `arm_joint5`까지 순서대로 5차원. 위치 단위 rad, 힘 한계 2 Nm, URDF 속도 상한은 0.5 rad/s입니다. PhysX의 순간 초과를 줄이기 위해 최종 실행 설정은 0.4 rad/s로 제한합니다. 학습은 0.5 rad/s 설정으로 했으며 최종 평가는 0.4 rad/s 설정으로 다시 수행합니다.
- 도달 기준: `arm_link5` 원점. 실제 그리퍼 끝의 보정된 TCP가 아닙니다. 원본에는 그리퍼 개폐 관절이 없습니다.
- 목표: 관절 공간에서 seed 12로 2,048개 자세를 샘플링한 FK 위치입니다. 기구학적 도달 가능성만 보장하며 충돌 없는 자세를 보장하지 않습니다.
- 관측: 관절 위치 5, 속도 5, 목표 pose 7, 이전 행동 5, 목표 상대 위치 3 = 25차원.
- 보상: 거리 감점 -10/m, 성공 보너스 10, 행동 크기·변화·속도 감점. 성공은 1.5 cm 이내 한 프레임 도달이며 정지 유지 판정이 아닙니다.

## 준비와 실행

저장소 루트에서 실행합니다. ZIP은 `assets/vendor/`에 압축 해제합니다. `r12_runtime.sh`는 이 장비의 기존 Sim 6.1 설치를 재사용하는 작업 전용 `.venv-r12`를 사용합니다. 다른 장비에서는 먼저 INSTALL.md의 EA 환경을 준비하거나 아래 스크립트의 환경 경로를 지정합니다. 사용자 승인 없이 라이선스 동의를 자동 설정하지 않습니다.

```bash
export R12_SIM_SITE="$HOME/isaacsim6_venv/lib/python3.12/site-packages"
export R12_LAB_SITE="$HOME/IsaacLab/.venv/lib/python3.12/site-packages"
git clone --depth 1 --branch v3.0.0-EA https://github.com/isaac-sim/IsaacLab.git ../IsaacLab-3.0-EA
bash scripts/install_r12_runtime.sh
# NVIDIA 이용약관에 동의한 경우에만 설정
export OMNI_KIT_ACCEPT_EULA=YES
bash scripts/r12_runtime.sh python scripts/prepare_r12.py
.venv-cpu/bin/python scripts/prepare_r12_ros.py
.venv-cpu/bin/python scripts/generate_r12_xrdf.py
.venv-cpu/bin/python -m arm_practice.preflight models/r12/r12_arm.urdf configs/r12_robot.json --require-usd
bash scripts/r12_runtime.sh train --rl_library rsl_rl --task Practice-Reach-R12 \
  --num_envs 32 --max_iterations 600 physics=isaacsim_physx
```

실행 환경은 큰 Sim 패키지를 읽기 전용으로 재사용하며 EA Python 소스, Warp 1.16.0, Newton 1.5.2, RSL-RL 5.4.1을 별도 환경에 설치합니다. 이 방식은 새 장비의 `uv sync --frozen` 전체 환경과 같지 않습니다. 실제 설치 목록은 `reports/local/r12-runtime-freeze.txt`에 기록합니다. Kit의 USD 바인딩과 네이티브 라이브러리를 함께 선택해 기존 standalone USD와의 ABI 충돌을 피합니다.

## 평가와 재생

```bash
export CHECKPOINT=/absolute/path/to/model_599.pt
bash scripts/r12_runtime.sh python scripts/evaluate_r12.py \
  --checkpoint "$CHECKPOINT" --episodes 64 --num-envs 16 \
  --output reports/local/r12_policy_eval.json
bash scripts/r12_runtime.sh play --rl_library rsl_rl --task Practice-Reach-R12 \
  --checkpoint "$CHECKPOINT" --num_envs 1 --viz kit physics=isaacsim_physx
```

평가는 새로운 seed 2026의 FK 목표를 사용합니다. 성공률, 평균 스텝 위치 오차, 관절 제한 위반, NaN, 베이스 이동, 최대 관절 속도를 기록합니다. 관측 잡음은 평가 때 끕니다. 평가 출력 폴더의 `exported/`에 TorchScript와 ONNX를 저장합니다. 초기 범용 설정의 22차원 체크포인트와 개선된 25차원 체크포인트는 호환되지 않습니다.

## ROS 2 Lyrical

MoveIt 패키지와 ros2_control이 설치되어야 합니다.

```bash
sudo apt-get install -y ros-lyrical-moveit ros-lyrical-ros2-control ros-lyrical-ros2-controllers
source /opt/ros/lyrical/setup.bash
colcon --log-base reports/local/colcon_logs build \
  --base-paths assets/vendor/R12_NO_USB_URDF_USD ros2 \
  --build-base reports/local/ros_build --install-base reports/local/ros_install --symlink-install
bash scripts/r12_ros.sh demo
```

`demo`는 GenericSystem 가상 하드웨어로 실행합니다. Sim이나 실물의 궤적 실행과 동일하지 않습니다. 기본 ROS domain은 78이며 localhost로 제한합니다. SRDF는 팔 체인과 home, 인접 링크 충돌 제외를 정의합니다. 5축의 위치 전용 IK를 사용합니다. 가속도 0.5 rad/s²와 jerk 5 rad/s³는 보수적인 실습 설정으로 실기 사양이 아닙니다.

cuMotion용 `r12.xrdf`는 원본 collision의 box/cylinder/sphere를 둘러싸는 890개 구로 만든 보수적 초안입니다. 상세 visual의 정밀 충돌 모델이 아닙니다. `bash scripts/r12_ros.sh cumotion`으로 로딩을 시험할 수 있으며, home에서 작은 관절 목표까지 자기충돌 검사를 포함한 계획을 검증했습니다. 전체 작업공간 안전성은 별도 검증 대상입니다.

Sim 터미널(ROS setup을 source하지 않은 새 터미널):

```bash
export OMNI_KIT_ACCEPT_EULA=YES
bash scripts/r12_bridge.sh --seconds 120
```

별도 Lyrical 터미널:

```bash
source /opt/ros/lyrical/setup.bash
export ROS_DOMAIN_ID=78 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
python3 scripts/check_r12_bridge.py --output reports/local/r12_bridge_check.json
# 검사 종료 후 가상 궤적 서버 실행
python3 scripts/r12_trajectory_server.py
```

또 다른 Lyrical 터미널에서 동일 domain을 설정하고 `python3 scripts/check_r12_trajectory.py`로 액션 실행을 검사합니다. 서버는 즉시 시작하는 위치 궤적을 선형 보간하며, 이름·위치·구간 속도를 확인하고 피드백 지연 시 중단합니다. `/r12/arm_controller/follow_joint_trajectory`는 Sim 전용입니다. 전체 ros2_control/MoveIt 통합을 대체하는 실물 드라이버가 아닙니다.

Sim↔Lyrical 검사 스크립트는 `r12_sim_bridge.py`와 `check_r12_bridge.py`입니다. Sim 프로세스는 bundled Jazzy 라이브러리, 검사는 별도 Lyrical 프로세스를 사용합니다. 검사 명령은 `/r12/joint_commands`로 첫 팔 관절 0.1 rad를 보내고 `/r12/joint_states` 응답을 확인합니다. ROS action 기반 궤적 실행 검증과 구분합니다.

## 모델의 검증 한계

원본의 전체 4 kg 가정 질량, 단순 충돌 프록시 및 내부 자기충돌 필터를 계승합니다. 학습 성공은 실물의 하중·접촉·집기·전복 안전성을 증명하지 않습니다. 이동 베이스 학습, 그리퍼 집기, 실측 TCP·질량, 모터 드라이버 연결에는 추가 모델과 장비 정보가 필요합니다.

## 설치 후 통합 검사

위 Sim 브리지와 궤적 서버를 실행한 상태에서 별도 터미널에 `bash scripts/r12_ros.sh sim`을 실행합니다. `demo`와 `sim`을 동일 domain에서 동시에 실행하지 마세요.

```bash
source /opt/ros/lyrical/setup.bash
export ROS_DOMAIN_ID=78 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
R12_STATE_TOPIC=/r12/joint_states R12_TARGET=0.15 \
R12_CHECK_OUTPUT=reports/local/r12_moveit_sim_check.json python3 scripts/check_r12_moveit.py
```

Mock 검사에는 `demo`를 실행하고 `python3 scripts/check_r12_moveit.py`를 사용합니다. cuMotion 서버 실행 후 동일 ROS domain에서 `python3 scripts/check_r12_cumotion.py`로 계획을 확인합니다.

## 확대 가동범위 탐색과 경로 회귀 검사

원본 README의 관절 한계는 검토용 값이며 기계적 최대각 인증값이 아닙니다. `prepare_r12_exploration.py`는 원본을 보존하고 팔 5축을 ±180°로 설정한 별도 URDF/USD 및 `configs/r12_exploration_robot.json`을 생성합니다. 이는 탐색 한계이며 허용 작업영역이나 실제 모터 사양을 뜻하지 않습니다. 확대 MoveIt 모델은 팔 상세 STL과 베이스 원본 충돌 프록시를 사용합니다. USD의 질량, 2 N·m 구동 한계와 원본 충돌 프록시는 유지합니다. 기존 학습 정책은 확대 범위에서 재검증/재학습되지 않았습니다.

상세 형상 검사는 `inspect_r12_geometry.py`로 수행합니다. 원본 삼각형의 FCL 교차를 5° 간격으로 검사하며 인접 링크는 영점에서도 겹칩니다. 따라서 비인접 링크 교차가 없는 구간도 인접부 기계적 스토퍼, 케이블, 연속 경로 안전성을 보증하지 않습니다. `render_r12_angles.py`는 원본 STL의 여러 자세를 렌더링합니다. 추가 도구는 `python-fcl`, `trimesh`, `vtk`입니다.

원본 범위 경로 계획:

```bash
bash scripts/r12_ros.sh demo
# 별도 터미널
source /opt/ros/lyrical/setup.bash
export ROS_DOMAIN_ID=78 ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
PYTHONPATH="$PWD/src:$PYTHONPATH" python3 scripts/validate_r12_paths.py
```

고정 10개, 개별 관절 최소/최대 10개, 동시 극한 조합 32개, 유효 자세 무작위 100쌍, 직선 경로가 막히는 장애물 10개를 기록합니다. 경로를 0.02 rad 이하 간격으로 보간 검사합니다. 계획 실패도 결과에 남깁니다.

확대 범위는 새 터미널에서 `R12_EXPLORATION=1 bash scripts/r12_ros.sh demo`를 실행하고, 검사에 `R12_ROBOT_CONFIG=configs/r12_exploration_robot.json` 및 별도 `R12_PATH_OUTPUT`을 지정합니다. `validate_r12_wide_demos.py`는 큰 각도의 대표 10개 목표를 검사합니다.

Sim 실행에는 아래 세 프로세스를 같은 ROS domain으로 실행합니다. 기존 demo/sim 및 다른 검증기와 동일 domain에서 중복 실행하지 마세요.

```bash
# ROS setup을 source하지 않은 터미널
OMNI_KIT_ACCEPT_EULA=YES bash scripts/r12_bridge.sh --seconds 900 \
  --usd-path models/r12/r12_exploration.usda --scene-file reports/local/r12_wide_scene.json
# Lyrical 터미널: 확대 전용 가상 궤적 서버
R12_ROBOT_CONFIG=configs/r12_exploration_robot.json python3 scripts/r12_trajectory_server.py
# Lyrical 터미널: 기록한 경로 실행
R12_ROBOT_CONFIG=configs/r12_exploration_robot.json \
R12_PATH_OUTPUT=reports/local/r12_wide_arm_mesh_demos.json \
R12_EXEC_OUTPUT=reports/local/r12_wide_execution.json \
R12_SCENE_FILE=reports/local/r12_wide_scene.json \
PYTHONPATH="$PWD/src:$PYTHONPATH" python3 scripts/execute_r12_paths.py
```

`R12_PATH_OUTPUT`은 실행 단계에서는 읽을 계획 JSON입니다. 장면 JSON은 검증기와 Sim 사이의 로컬 파일이며 장애물 추가/제거를 ACK로 확인합니다. 경로 서버 외에 별도의 MoveIt 계획 서버가 필요합니다. `R12_EXEC_SAMPLE=1`은 무작위 경로 중 index 0,10,...90을 실행하고 동시 극한 조합은 생략합니다. `R12_RESUME`은 이전 실행 JSON의 통과 사례만 재사용합니다. 생략, 계획 실패, 실행 실패를 성공으로 합산하지 않습니다.

현재 2번 관절의 확대 자세에서는 원본 가정 질량으로 계산한 중력 토크가 2 N·m를 초과할 수 있습니다. 각도만 넓혀도 유지·복귀가 보장되지 않습니다. 구동력을 임의로 높인 결과를 실제 모터 성능으로 해석하면 안 됩니다.
